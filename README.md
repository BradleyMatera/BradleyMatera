## About me

I have a **B.S. in Web Development from Full Sail University** and certifications as an **AWS Solutions Architect – Associate** and **AWS AI Practitioner**. My strongest foundation is in web development, JavaScript, React, Node.js, APIs, and working through cloud and infrastructure concepts.

In 2025 I completed a **12-week AWS Cloud Support Associate internship** in Seattle. My work was performed in Amazon training, lab, and project environments rather than production customer systems. My internship project used AWS services including S3, Lambda, DynamoDB, and a static frontend layer.

I also served as a **U.S. Army Combat Medic with the 82nd Airborne Division** before moving into technology.

### A note about AI-assisted development

I use AI heavily when I build, learn, research, prototype, and debug. That lets me experiment with systems much larger than I could reasonably hand-code alone, but I do **not** treat generated code as proof that I personally have expert-level knowledge of every technology inside those repositories.

A lot of my GitHub is intentionally made up of **experiments, prototypes, demos, learning labs, and AI-assisted builds**. I try to be clear about that distinction. If I am interviewing for a role, I would rather explain what I actually understand, what I personally verified, and where I still need to learn than have a repository make me look more senior than I am.

## Selected work and experiments

<details open>
<summary><strong>Scout / ProjectHub — experimental AI systems project</strong></summary>
<br>

An ongoing AI-assisted project where I experiment with building an assistant around a small amount of compute instead of assuming a giant model solves everything.

Current experiments include local retrieval, BM25, reciprocal-rank fusion, short-term conversational state, deterministic evidence tools, response validation, Docker-based testing, and interchangeable inference providers.

This is a **research/learning project**, not evidence that I personally invented or mastered every technique used inside it.

**Repository:** [BradleyMatera/ProjectHub](https://github.com/BradleyMatera/ProjectHub)

</details>

<details>
<summary><strong>AWS Serverless Metadata Workflow — public reconstruction of internship work</strong></summary>
<br>

A public reconstruction and expansion of the type of serverless metadata workflow I worked with during my AWS internship. It uses S3, Lambda, DynamoDB, AWS SAM/CloudFormation, retries, monitoring, tests, and failure handling.

The repository is intentionally documented as a **public reconstruction**. It does not claim that the public code is Amazon production code, that I owned customer infrastructure, or that I had unrestricted production access.

**Repository:** [BradleyMatera/AWS-Serverless-Metadata-Workflow](https://github.com/BradleyMatera/AWS-Serverless-Metadata-Workflow)

</details>

<details>
<summary><strong>Interactive Systems Lab — AI-assisted frontend / Babylon.js sandbox</strong></summary>
<br>

A large experimental browser playground containing 3D scenes, simulations, UI concepts, engineering visualizations, and playable demos. Much of the implementation was created and iterated with AI assistance while I used the project to explore browser graphics, Babylon.js, interfaces, and interaction design.

**Repository:** [BradleyMatera/GameTesting](https://github.com/BradleyMatera/GameTesting)  
**Live demo:** [Interactive Systems Lab](https://bradleymatera.github.io/GameTesting/)

</details>

<details>

Website work for a local commercial work-truck seller. The project focuses on straightforward inventory presentation, responsive layouts, accessible pages, local discoverability, and a simple workflow for marking trucks available, pending, or sold.

**Repository:** [BradleyMatera/pcstrucksales](https://github.com/BradleyMatera/pcstrucksales)

</details>
